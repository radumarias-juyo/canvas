## Scope

1. A `memory` table in `UserDirectory`: id, scope (`user` = just me, `agent` = this agent, `chat` = everyone in a chat),
   agent id, chat id, text, source (learned in a conversation / added by a person), uses, pinned, confirmed,
   forgotten_at, created/updated. Off-the-record chats are refused in code (T5's `shared/chat-kinds.ts` rule).
2. Agent tools: `memory_note` (save a preference; a fact that changes what an agent computes is saved **unconfirmed**
   until someone confirms it, like skills), `memory_recall`/search (scoped to what this turn may see: the user's notes
   only for the owner's own turns, the chat's notes for that chat, the agent's notes for that agent), `memory_forget`.
   Notes in scope go into the prompt as a section (cache-friendly: only grows within a session); `uses` counts reads.
   Memory per chat: what an agent learns in a shared chat stays with that chat unless its owner moves it to their own.
3. **"What it knows"** UI: a Knows tab on the agent page (T2's `TABS`) and an account-level Memory view: notes with scope,
   source, use count and pin; edit, pin, forget, **show forgotten** with undo; confirm unconfirmed facts; connected data
   (the MCP servers and what each covers), documents (the user's files) and skills.
4. Data export/import of notes (not of off-the-record ones, which never exist).

5. **What is there now** (merged into feat/agents): `shared/chat-kinds.ts` exports `mayLeave(leaving, ...kinds)` and
   `answersEveryMessage`; `ChatAgent.chatKind()` and `UserDirectory.chatKind(id)` give a chat's kind. Nothing calls
   `mayLeave` yet: memory is its first user. The agent page's tabs are T2's `TABS` in `src/agents/AgentPage.tsx`
   (Setup ships; the scheduled-runs task adds Workflow and Runs, so merge feat/agents in often). Notes must not reach a
   page chat's joiners or a member's turn unless their scope says so (the security model under "Rules for every task" in plan.md).
