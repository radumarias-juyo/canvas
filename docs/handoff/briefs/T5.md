# T5 · Chat kinds and "around the chat"

Repo `radumarias/pi-artifacts`. Read first: `/mnt/project-files/agents-impl/plan.md`, then section 8 of
`specs/multi-agent-proposal.txt` ("Kinds of chat, and staying in the loop") and the "Chat kinds, branches and follows"
table in `specs/tech-spec.md`. Base branch and PR target: **`feat/agents`**.

## Goal

A chat has a kind that sets who sees it, when agents answer and what may leave it; and people keep track of many chats.

## Scope

1. **Four kinds**: private (only the owner; agents answer every message), group (the people added; agents only when
   called), on a page (anyone who can open the linked artifact can join; the page and its current version are in the
   agent's context; each new version reaches the agents' sessions as a passive write), off the record (only people added
   by hand; nothing leaves: no memory notes, no search, no routine reads, no feed previews). Store the kind (and page id)
   in the chat object, copy it to each member's sidebar row (`UserDirectory.chats` / `shared_chats`). Expose
   `chatKind(chatId)` for other stores, and `shared/chat-kinds.ts` with the type and the rules as functions (what may
   leave, when agents answer) so T7 (memory) and T9 (feed) call them.
2. **The kind chip** beside the chat title (owner changes it there). Narrowing (group → private, → off the record) first
   lists who loses access, then removes them in the same request; widening says everyone added sees the whole history.
   Adding the first member makes a private chat a group ("Radu added Maria · the chat is now a group" and "pi now
   answers only when someone calls @pi" as system lines).
3. **Chats on a page**: from an artifact's page, "Discuss" opens (or makes) the chat linked to it
   (`page_chats(artifact_id, chat_id)` in the owner's directory); joining checks the same access as opening the artifact.
4. **Add by tagging**: tagging someone who isn't in the chat shows the card "@Maria isn't in this chat. Adding them shows
   them everything said so far" with Not now / New chat with them / Add to this chat. There is no people directory yet:
   offer the people the user already shares other chats with as the names the `@` picker knows; for them "Add" adds them
   directly (owner only, with that warning) and tells them through their sidebar socket; for anyone else the card copies
   an invite link. "New chat with them" starts a new group with none of the earlier messages.
5. **Branch off** in a message's menu: a new chat carrying the conversation up to that message, same kind, a link back;
   the original shows a quiet line that a branch exists. The new chat's pi session is filled with passive writes (one
   summary write when long), and its log copies the entries up to the message.
6. **Staying in the loop**, per person in the sidebar: pin, rename, copy link, mark unread, **close** (hides the chat for
   you until someone tags you again), leave (members), delete (owner, exists). **Unread first**: chats with unread
   messages are bold and move to the top, with an optional grouping by date or kind.
