   tokens (`clearTokensIf` sets `signed_in_at` NULL), so from then on the server drops out: later runs go ahead
   without it and end `sent`, with no wait and no notice. When the owner signs in again, `runner.signedIn` restarts the
   oldest waiting run (day 1's), which then posts after days 2-4. Fix: decide by whether the owner has a sign-in record
   for the server (the `mcp_auth` row survives `clearTokensIf`; Disconnect deletes it). In `AgentRunner.signedIn`,
   skip (as not_today) a waiting run when a newer run of the agent with the same test flag has ended since. Test: a
   refused refresh, then the next run still waits.

3. `worker/chat-agent.ts` ~3296 `#rebuildPage`: a rebuild drops the page's write tools (on purpose), but nobody is told

## Merged, round 3 follow-ups (checked at 5d99a57; #116 squash-merged as 26efe32)

Items 11, 12, 14 and 15 are fixed. 13 is partly fixed: two reports never post now, but the stale check still asks
again right after a sign-in that landed during a newer run's check. Everything below is low. Put it in a bundle as

16. `worker/agents/runs/executor.ts` ~287 `#waitForSignIn`: a run still going (pre-check, or a later look that throws
    SignInNeeded) when the owner turns the agent off ends needs_sign_in after `#skipWaiting` already ran. It asks the
    owner to sign in for an off agent, adds a Needs-you item, and once the agent is on again a sign-in restarts and
    posts that stale run (scratch test: ended 'sent' with one delivery). Fix: for a real run, read
    `host.definition(agent.id)` there; when it is off or gone, end the run not_today ("Skipped: @x was turned off.").
17. `worker/agents/runs/runner.ts` ~184/396 `signedIn`: it holds the waiting list across `await host.definition()`.
    A run that `skipReplaced` or `#skipWaiting` ends meanwhile is ended again (endings [T0:not_today, T0:not_today]);
    `restart()` on a pruned row inserts a fresh row. Fix: skip with `AND status = 'needs_sign_in'` and fire onEnded only
    when a row changed; have `restart()` report whether it changed one and count/start only then.
18. `runner.ts` ~386 (13's tail): when signedIn leaves an older run waiting because a newer one is going, and that one
    then ends failed (or waits on other servers), nothing wakes the older run: the chat left mcp_waiting, so no later
    sign-in reaches it, and its Needs-you item stays while the owner is signed in. Fix: record the deferral on the run
    (`detail.released`) and, when the going run ends without going, restart the newest deferred one, or keep the chat in
    mcp_waiting for that case. Also, when a sign-in for the server landed during the newer run's check, check once more
    instead of asking again.
19. `shared/sign-ins.ts` ~53 and `src/agents/RunsTab.tsx` ~217: "Disconnect it, and runs go on without it" is false for an
    agent whose steps read the server (look crm.x). After Disconnect the pre-check still checks crm, the run waits again,
    and the new notice has no Disconnect (crm isn't known any more), so every later run brings it back. Fix: offer
    Disconnect / "go on without it" only when no waiting run reads that server in a step (the chat can say so in
    needed()'s context); otherwise say the agent reads it in a step, so change the agent or turn it off. Or, after a
    Disconnect, end such runs failed with that reason.

## Round 4 (checked #118 at e4e88f6)

Items 16-18 are fixed, and so is the feed's item 23. 19 is partly fixed. I'm merging #118. Everything below is low. It

20. `worker/agents/runs/executor.ts` ~321 `#wakeDeferred`: the wake isn't durable. If `host.definition()` throws, or the
    object resets during it, the released run stays needs_sign_in with nothing to wake it. resume() restarts only
    running rows, and the chat already left mcp_waiting. Fix: restart the released row synchronously as the newer run
    ends, before any await. resume() then picks it up, and #turnedOffNow covers an off or deleted agent. Or have
    resume() also wake released runs whose newer runs no longer go.
21. `executor.ts` ~323: the wake restarts the released run without asking `newer()` again. With R2 and R3 both going,
    R2 failing wakes R1 while R3 still runs, and both post (the older report can land after the newer one). When R2
    itself ends needs_sign_in on another server, waking R1 can also give two reports. Fix: after the definition read,
    ask `runs.newer()`. On went, skip R1 as replaced. On going, leave it released. When the run that ended is itself
    waiting, skip the older released run as replaced by it.
22. `worker/agents/runs/runner.ts` ~374 (the going branch): `released` is built from `run.detail` as read before the
    definitions await. Two sign-ins at once (crm, mail) leave only one released, and the newer run then asks again.
    Fix: re-read the row after the await, and merge the mark only while the row still waits.
23. `executor.ts` ~299: the late-sign-in recheck's await sits between the off check and the wait. A turn-off during it
    still ends the run needs_sign_in. Fix: check off again after the recheck.
24. `worker/mcp/sign-ins.ts` ~308: a notice made without stepReads (the keep-alive alarm, or after Dismiss) offers
    "Disconnect it, and runs go on without it" for a server a step reads, which is 19's loop again. Fix: work out
    stepReads from what is waiting, e.g. a step_reads column per (server, chat) in mcp_waiting, read in list()/#tell.
    For the keep-alive, have setRunServers record which servers are read in a step.
25. `src/SignIns.tsx` ~146: the account-menu row still says "runs wait for it until you sign in again, or Disconnect"
    for a server that a step reads. Use stepReads there too. The button can stay.
26. `shared/sign-ins.ts` ~51: following "change its steps" doesn't end the wait. The run already waiting still waits
    on crm, and the notice keeps the advice. Fix: when an agent's definition changes, re-check its waiting runs whose
    new step servers drop the server, and clear step_reads when no waiting run still reads it. Or, simpler, say
    "change its steps, then Disconnect it".
